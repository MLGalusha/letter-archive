The dynamic program is page-scoped, not whole-letter scoped. Exact transcript
page markers make that boundary trustworthy, prevent cross-page split/merge
matches, and avoid the near-gigabyte memory growth observed in an early

recognition becomes almost entirely unreadable after the initial lines.

## Stage-1 flow repair — 2026-07-30

Final candidate:
`mccatmus-flow-aware-v2f-20260730`

This is a deliberately narrow repair of the first content-aware matcher. It:

- Keeps standalone editorial placeholders such as `[illegible]` unlocated
  instead of allowing them to consume real image lines.
- Uses preserved orientation and geometry to repair a clearly inverted
  adjacent pair.
- Honors explicit reading order and refuses to transpose across known regions.
- Keeps minority-orientation detections visible but marks them as deferred for
  a later rotated-text pass.
- Supports both the legacy normalized layout artifact and native Kraken 7
  `PageLayout` v2 without flattening either representation on disk.

The six changed assignments are explainable:

1. Three standalone `[illegible]` placeholders no longer steal detections.
2. `2 Ep. Aug 10/88` moves to the visible date line.
3. `My dear Sadie,` moves to the visible greeting line.
4. One 86.6° fragment is removed from a horizontal split on
   `009-19470830-L01-02` and deferred for rotated review; the remaining segment
   has higher text similarity.

The following body line remains a split over the short `22` detection and its
main handwritten line. That is intentional at this stage: OCR text length
alone is not safe evidence that a small polygon is noise, so the admin keeps
both pieces available for a human correction.

An earlier ablation discounted all short OCR fragments. It was rejected after
the cohort replay moved a real date onto a YMCA logo, discarded the genuine
short `P.E.I.` and `up.` lines, and shifted a large page block. Regression tests
now protect those cases. The final candidate contains none of that global
short-fragment behavior.

## First visual case study

Subject: `005-19150813-L01-01`

- One-page letter.
- Current transcript matches a saved human version.
- 41 nonblank transcript lines.
- 44 Kraken detections.
- 44/44 detections received local HTR fingerprints.

The initial dynamic program exposed a bad scoring behavior: inexpensive
opposing gap blocks let the matcher abandon both noisy suffixes. Direct
gap-to-gap switching was prohibited and extension costs were raised relative
to plausible noisy matches. A regression test now covers this failure.

Current mapping shape:

| Operation | Count |
|---|---:|
| One-to-one matches | 37 |
| One transcript line split across two detections | 2 |
| Two transcript lines merged into one detection | 1 |
| Skipped detections | 2 |
| Unlocated transcript lines | 0 |

The existing typed-Kraken frontend path assigns the first transcript line to
the first detected segment when there are more segments than transcript lines.
On this page, the first two detections are stray vertical lines near the lower
left. That starts the transcript in the wrong place and shifts subsequent
content.

The content-aware path instead:

- Joins `970 Lexington Ave` to the two top address detections.
- Continues through the page without a cascading offset.
- Skips the two stray vertical detections.
- Places the final signature at the bottom-right segment.

This is visually promising, but every relationship remains marked
`ambiguous`. No automatic acceptance threshold has been calibrated against
human mapping truth yet.

## Human review and measurement surface

The local admin route
`/admin/layout-benchmark/alignment` now provides:

- A scan-first canvas with native Kraken polygons and baselines.
- Reference transcript text and its source tier beside Kraken’s rough reading.
- Explicit split, merge, skipped, unlocated, confidence, and alternative states.
- A distinct deferred state for rotated detections that are intentionally held
  out of the current horizontal-flow pass.
- Reviewer decisions tied to the exact artifact hash.
- Corrected segment selection, compact failure tags, active review time, and
  repair-action counts.
- Separate judgments for text that is absent from the page and text that is
  visible but has no usable Kraken line polygon.
- A reviewer-scoped scorecard for exact accuracy, proposed auto-accept
  precision/coverage, segment-link precision/recall/F1, alternative recall,
  failure modes, operation breakdowns, and effort.

Stale browser tabs cannot attach a verdict to regenerated mappings: the API
checks the artifact hash immediately before its atomic write and returns a
conflict instead. Concurrent saves for the same reviewer and page are also
serialized so two tabs cannot silently overwrite one another.

No fabricated human verdicts are present. Consequently, every review-derived
accuracy or effort metric is currently `null`, not zero.

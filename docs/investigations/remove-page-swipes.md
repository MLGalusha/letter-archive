# Remove route-changing swipes

The old public route wrapper enabled cyclic swipes only on Home, Collections, Journal, About, and Support, and only for a coarse primary pointer. Collection detail had an independent handler gated by adjacent collection availability. Both shared a gesture hook with direction/distance thresholds, editable-focus suppression, and `data-swipe-ignore` exclusions. Letter detail already had no route-changing swipe handler; its gestures change scans within the current letter. These different activation rules explain why the same movement could behave differently by page and starting area.

Removed the route wrapper, collection gesture setup and transforms, shared route-swipe hook, now-unused touch-device hook, obsolete tests/mocks, and child opt-out attributes. No replacement navigation abstraction is necessary: the header links and existing shared scrubber retain explicit navigation. CardCarousel, native scan scrolling, and fullscreen scan gestures remain independent content interactions. Browser-owned history gestures are outside this application behavior.

Validation: Chromium and WebKit tests dispatch both horizontal touch directions across all five site sections, a collection with previous/next neighbors, and a letter with neighbors. URLs remain unchanged, content does not translate, and explicit links/arrows still navigate. Existing card-carousel tests also pass, including native Chromium touch input, mouse dragging, keyboard control, and the conditional text-card outline. Production build and lint pass; collection/carousel and letter/responsive unit coverage passed. The read-only phone preview includes this change plus the earlier collection-width and homepage-border fixes. No deployment performed.
